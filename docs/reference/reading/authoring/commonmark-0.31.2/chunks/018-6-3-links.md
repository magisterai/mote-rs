## 6.3 Links

A link contains [link text](018-6-3-links.md#link-text) (the visible text), a [link destination](018-6-3-links.md#link-destination)
(the URI that is the link destination), and optionally a [link title](018-6-3-links.md#link-title).
There are two basic kinds of links in Markdown. In [inline links](018-6-3-links.md#inline-link) the
destination and title are given immediately after the link text. In
[reference links](019-continuation-19.md#reference-link) the destination and title are defined elsewhere in
the document.

<a id="link-text"></a>

A [link text](018-6-3-links.md#link-text) consists of a sequence of zero or more
inline elements enclosed by square brackets (`[` and `]`). The
following rules apply:

- Links may not contain other links, at any level of nesting. If
  multiple otherwise valid link definitions appear nested inside each
  other, the inner-most definition is used.
- Brackets are allowed in the [link text](018-6-3-links.md#link-text) only if (a) they
  are backslash-escaped or (b) they appear as a matched pair of brackets,
  with an open bracket `[`, a sequence of zero or more inlines, and
  a close bracket `]`.
- Backtick [code spans](014-6-inlines.md#code-span), [autolinks](021-6-5-autolinks.md#autolinks), and raw [HTML tags](021-6-5-autolinks.md#html-tag) bind more tightly
  than the brackets in link text. Thus, for example,
  `` [foo`]` `` could not be a link text, since the second `]`
  is part of a code span.
- The brackets in link text bind more tightly than markers for
  [emphasis and strong emphasis](015-6-2-emphasis-and-strong-emphasis.md#emphasis-and-strong-emphasis). Thus, for example, `*[foo*](url)` is a link.

<a id="link-destination"></a>

A [link destination](018-6-3-links.md#link-destination) consists of either

- a sequence of zero or more characters between an opening `<` and a
  closing `>` that contains no line endings or unescaped
  `<` or `>` characters, or
- a nonempty sequence of characters that does not start with `<`,
  does not include [ASCII control characters](002-1-3-about-this-document.md#ascii-control-character)
  or [space](002-1-3-about-this-document.md#space) character, and includes parentheses only if (a) they are
  backslash-escaped or (b) they are part of a balanced pair of
  unescaped parentheses.
  (Implementations may impose limits on parentheses nesting to
  avoid performance issues, but at least three levels of nesting
  should be supported.)

<a id="link-title"></a>

A [link title](018-6-3-links.md#link-title) consists of either

- a sequence of zero or more characters between straight double-quote
  characters (`"`), including a `"` character only if it is
  backslash-escaped, or
- a sequence of zero or more characters between straight single-quote
  characters (`'`), including a `'` character only if it is
  backslash-escaped, or
- a sequence of zero or more characters between matching parentheses
  (`(...)`), including a `(` or `)` character only if it is
  backslash-escaped.

Although [link titles](018-6-3-links.md#link-title) may span multiple lines, they may not contain
a [blank line](002-1-3-about-this-document.md#blank-line).

<a id="inline-link"></a>

An [inline link](018-6-3-links.md#inline-link) consists of a [link text](018-6-3-links.md#link-text) followed immediately
by a left parenthesis `(`, an optional [link destination](018-6-3-links.md#link-destination), an optional
[link title](018-6-3-links.md#link-title), and a right parenthesis `)`.
These four components may be separated by spaces, tabs, and up to one line
ending.
If both [link destination](018-6-3-links.md#link-destination) and [link title](018-6-3-links.md#link-title) are present, they *must* be
separated by spaces, tabs, and up to one line ending.

The link’s text consists of the inlines contained
in the [link text](018-6-3-links.md#link-text) (excluding the enclosing square brackets).
The link’s URI consists of the link destination, excluding enclosing
`<...>` if present, with backslash-escapes in effect as described
above. The link’s title consists of the link title, excluding its
enclosing delimiters, with backslash-escapes in effect as described
above.

Here is a simple inline link:

<a id="example-482"></a>

[Example 482](018-6-3-links.md#example-482)Try It



```
[link](/uri "title")
```






```
<p><a href="/uri" title="title">link</a></p>
```




The title, the link text and even
the destination may be omitted:

<a id="example-483"></a>

[Example 483](018-6-3-links.md#example-483)Try It



```
[link](/uri)
```






```
<p><a href="/uri">link</a></p>
```




<a id="example-484"></a>

[Example 484](018-6-3-links.md#example-484)Try It



```
[](./target.md)
```






```
<p><a href="./target.md"></a></p>
```




<a id="example-485"></a>

[Example 485](018-6-3-links.md#example-485)Try It



```
[link]()
```






```
<p><a href="">link</a></p>
```




<a id="example-486"></a>

[Example 486](018-6-3-links.md#example-486)Try It



```
[link](<>)
```






```
<p><a href="">link</a></p>
```




<a id="example-487"></a>

[Example 487](018-6-3-links.md#example-487)Try It



```
[]()
```






```
<p><a href=""></a></p>
```




The destination can only contain spaces if it is
enclosed in pointy brackets:

<a id="example-488"></a>

[Example 488](018-6-3-links.md#example-488)Try It



```
[link](/my uri)
```






```
<p>[link](/my uri)</p>
```




<a id="example-489"></a>

[Example 489](018-6-3-links.md#example-489)Try It



```
[link](</my uri>)
```






```
<p><a href="/my%20uri">link</a></p>
```




The destination cannot contain line endings,
even if enclosed in pointy brackets:

<a id="example-490"></a>

[Example 490](018-6-3-links.md#example-490)Try It



```
[link](foo
bar)
```






```
<p>[link](foo
bar)</p>
```




<a id="example-491"></a>

[Example 491](018-6-3-links.md#example-491)Try It



```
[link](<foo
bar>)
```






```
<p>[link](<foo
bar>)</p>
```




The destination can contain `)` if it is enclosed
in pointy brackets:

<a id="example-492"></a>

[Example 492](018-6-3-links.md#example-492)Try It



```
[a](<b)c>)
```






```
<p><a href="b)c">a</a></p>
```




Pointy brackets that enclose links must be unescaped:

<a id="example-493"></a>

[Example 493](018-6-3-links.md#example-493)Try It



```
[link](<foo\>)
```






```
<p>[link](&lt;foo&gt;)</p>
```




These are not links, because the opening pointy bracket
is not matched properly:

<a id="example-494"></a>

[Example 494](018-6-3-links.md#example-494)Try It



```
[a](<b)c
[a](<b)c>
[a](<b>c)
```






```
<p>[a](&lt;b)c
[a](&lt;b)c&gt;
[a](<b>c)</p>
```




Parentheses inside the link destination may be escaped:

<a id="example-495"></a>

[Example 495](018-6-3-links.md#example-495)Try It



```
[link](\(foo\))
```






```
<p><a href="(foo)">link</a></p>
```




Any number of parentheses are allowed without escaping, as long as they are
balanced:

<a id="example-496"></a>

[Example 496](018-6-3-links.md#example-496)Try It



```
[link](foo(and(bar)))
```






```
<p><a href="foo(and(bar))">link</a></p>
```




However, if you have unbalanced parentheses, you need to escape or use the
`<...>` form:

<a id="example-497"></a>

[Example 497](018-6-3-links.md#example-497)Try It



```
[link](foo(and(bar))
```






```
<p>[link](foo(and(bar))</p>
```




<a id="example-498"></a>

[Example 498](018-6-3-links.md#example-498)Try It



```
[link](foo\(and\(bar\))
```






```
<p><a href="foo(and(bar)">link</a></p>
```




<a id="example-499"></a>

[Example 499](018-6-3-links.md#example-499)Try It



```
[link](<foo(and(bar)>)
```






```
<p><a href="foo(and(bar)">link</a></p>
```




Parentheses and other symbols can also be escaped, as usual
in Markdown:

<a id="example-500"></a>

[Example 500](018-6-3-links.md#example-500)Try It



```
[link](foo\)\:)
```






```
<p><a href="foo):">link</a></p>
```




A link can contain fragment identifiers and queries:

<a id="example-501"></a>

[Example 501](018-6-3-links.md#example-501)Try It



```
[link](#fragment)

[link](https://example.com#fragment)

[link](https://example.com?foo=3#frag)
```






```
<p><a href="#fragment">link</a></p>
<p><a href="https://example.com#fragment">link</a></p>
<p><a href="https://example.com?foo=3#frag">link</a></p>
```




Note that a backslash before a non-escapable character is
just a backslash:

<a id="example-502"></a>

[Example 502](018-6-3-links.md#example-502)Try It



```
[link](foo\bar)
```






```
<p><a href="foo%5Cbar">link</a></p>
```




URL-escaping should be left alone inside the destination, as all
URL-escaped characters are also valid URL characters. Entity and
numerical character references in the destination will be parsed
into the corresponding Unicode code points, as usual. These may
be optionally URL-escaped when written as HTML, but this spec
does not enforce any particular policy for rendering URLs in
HTML or other formats. Renderers may make different decisions
about how to escape or normalize URLs in the output.

<a id="example-503"></a>

[Example 503](018-6-3-links.md#example-503)Try It



```
[link](foo%20b&auml;)
```






```
<p><a href="foo%20b%C3%A4">link</a></p>
```




Note that, because titles can often be parsed as destinations,
if you try to omit the destination and keep the title, you’ll
get unexpected results:

<a id="example-504"></a>

[Example 504](018-6-3-links.md#example-504)Try It



```
[link]("title")
```






```
<p><a href="%22title%22">link</a></p>
```




Titles may be in single quotes, double quotes, or parentheses:

<a id="example-505"></a>

[Example 505](018-6-3-links.md#example-505)Try It



```
[link](/url "title")
[link](/url 'title')
[link](/url (title))
```






```
<p><a href="/url" title="title">link</a>
<a href="/url" title="title">link</a>
<a href="/url" title="title">link</a></p>
```




Backslash escapes and entity and numeric character references
may be used in titles:

<a id="example-506"></a>

[Example 506](018-6-3-links.md#example-506)Try It



```
[link](/url "title \"&quot;")
```






```
<p><a href="/url" title="title &quot;&quot;">link</a></p>
```




Titles must be separated from the link using spaces, tabs, and up to one line
ending.
Other [Unicode whitespace](002-1-3-about-this-document.md#unicode-whitespace) like non-breaking space doesn’t work.

<a id="example-507"></a>

[Example 507](018-6-3-links.md#example-507)Try It



```
[link](/url "title")
```






```
<p><a href="/url%C2%A0%22title%22">link</a></p>
```




Nested balanced quotes are not allowed without escaping:

<a id="example-508"></a>

[Example 508](018-6-3-links.md#example-508)Try It



```
[link](/url "title "and" title")
```






```
<p>[link](/url &quot;title &quot;and&quot; title&quot;)</p>
```




But it is easy to work around this by using a different quote type:

<a id="example-509"></a>

[Example 509](018-6-3-links.md#example-509)Try It



```
[link](/url 'title "and" title')
```






```
<p><a href="/url" title="title &quot;and&quot; title">link</a></p>
```




(Note: `Markdown.pl` did allow double quotes inside a double-quoted
title, and its test suite included a test demonstrating this.
But it is hard to see a good rationale for the extra complexity this
brings, since there are already many ways—backslash escaping,
entity and numeric character references, or using a different
quote type for the enclosing title—to write titles containing
double quotes. `Markdown.pl`’s handling of titles has a number
of other strange features. For example, it allows single-quoted
titles in inline links, but not reference links. And, in
reference links but not inline links, it allows a title to begin
with `"` and end with `)`. `Markdown.pl` 1.0.1 even allows
titles with no closing quotation mark, though 1.0.2b8 does not.
It seems preferable to adopt a simple, rational rule that works
the same way in inline links and link reference definitions.)

Spaces, tabs, and up to one line ending is allowed around the destination and
title:

<a id="example-510"></a>

[Example 510](018-6-3-links.md#example-510)Try It



```
[link](   /uri
  "title"  )
```






```
<p><a href="/uri" title="title">link</a></p>
```




But it is not allowed between the link text and the
following parenthesis:

<a id="example-511"></a>

[Example 511](018-6-3-links.md#example-511)Try It



```
[link] (/uri)
```






```
<p>[link] (/uri)</p>
```




The link text may contain balanced brackets, but not unbalanced ones,
unless they are escaped:

<a id="example-512"></a>

[Example 512](018-6-3-links.md#example-512)Try It



```
[link [foo [bar]]](/uri)
```






```
<p><a href="/uri">link [foo [bar]]</a></p>
```




<a id="example-513"></a>

[Example 513](018-6-3-links.md#example-513)Try It



```
[link] bar](/uri)
```






```
<p>[link] bar](/uri)</p>
```




<a id="example-514"></a>

[Example 514](018-6-3-links.md#example-514)Try It



```
[link [bar](/uri)
```






```
<p>[link <a href="/uri">bar</a></p>
```
