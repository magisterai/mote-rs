## 2.2 Tabs

Tabs in lines are not expanded to [spaces](002-1-3-why-is-a-spec-needed.md#space). However,
in contexts where whitespace helps to define block structure,
tabs behave as if they were replaced by spaces with a tab stop
of 4 characters.

Thus, for example, a tab can be used instead of four spaces
in an indented code block. (Note, however, that internal
tabs are passed through as literal tabs, not expanded to
spaces.)

<a id="example-1"></a>

[Example 1](003-2-2-tabs.md#example-1)



```
→foo→baz→→bim
```






```
<pre><code>foo→baz→→bim
</code></pre>
```




<a id="example-2"></a>

[Example 2](003-2-2-tabs.md#example-2)



```
  →foo→baz→→bim
```






```
<pre><code>foo→baz→→bim
</code></pre>
```




<a id="example-3"></a>

[Example 3](003-2-2-tabs.md#example-3)



```
    a→a
    ὐ→a
```






```
<pre><code>a→a
ὐ→a
</code></pre>
```




In the following example, a continuation paragraph of a list
item is indented with a tab; this has exactly the same effect
as indentation with four spaces would:

<a id="example-4"></a>

[Example 4](003-2-2-tabs.md#example-4)



```
  - foo

→bar
```






```
<ul>
<li>
<p>foo</p>
<p>bar</p>
</li>
</ul>
```




<a id="example-5"></a>

[Example 5](003-2-2-tabs.md#example-5)



```
- foo

→→bar
```






```
<ul>
<li>
<p>foo</p>
<pre><code>  bar
</code></pre>
</li>
</ul>
```




Normally the `>` that begins a block quote may be followed
optionally by a space, which is not considered part of the
content. In the following case `>` is followed by a tab,
which is treated as if it were expanded into three spaces.
Since one of these spaces is considered part of the
delimiter, `foo` is considered to be indented six spaces
inside the block quote context, so we get an indented
code block starting with two spaces.

<a id="example-6"></a>

[Example 6](003-2-2-tabs.md#example-6)



```
>→→foo
```






```
<blockquote>
<pre><code>  foo
</code></pre>
</blockquote>
```




<a id="example-7"></a>

[Example 7](003-2-2-tabs.md#example-7)



```
-→→foo
```






```
<ul>
<li>
<pre><code>  foo
</code></pre>
</li>
</ul>
```




<a id="example-8"></a>

[Example 8](003-2-2-tabs.md#example-8)



```
    foo
→bar
```






```
<pre><code>foo
bar
</code></pre>
```




<a id="example-9"></a>

[Example 9](003-2-2-tabs.md#example-9)



```
 - foo
   - bar
→ - baz
```






```
<ul>
<li>foo
<ul>
<li>bar
<ul>
<li>baz</li>
</ul>
</li>
</ul>
</li>
</ul>
```




<a id="example-10"></a>

[Example 10](003-2-2-tabs.md#example-10)



```
#→Foo
```






```
<h1>Foo</h1>
```




<a id="example-11"></a>

[Example 11](003-2-2-tabs.md#example-11)



```
*→*→*→
```






```
<hr />
```




<a id="insecure-characters"></a>

## 2.3 Insecure characters

For security reasons, the Unicode character `U+0000` must be replaced
with the REPLACEMENT CHARACTER (`U+FFFD`).

<a id="blocks-and-inlines"></a>

# 3 Blocks and inlines

<a id="blocks"></a>

<a id="inline"></a>

We can think of a document as a sequence of
[blocks](003-2-2-tabs.md#blocks)—structural elements like paragraphs, block
quotations, lists, headings, rules, and code blocks. Some blocks (like
block quotes and list items) contain other blocks; others (like
headings and paragraphs) contain [inline](003-2-2-tabs.md#inline) content—text,
links, emphasized text, images, code spans, and so on.

<a id="precedence"></a>

## 3.1 Precedence

Indicators of block structure always take precedence over indicators
of inline structure. So, for example, the following is a list with
two items, not a list with one item containing a code span:

<a id="example-12"></a>

[Example 12](003-2-2-tabs.md#example-12)



```
- `one
- two`
```






```
<ul>
<li>`one</li>
<li>two`</li>
</ul>
```




This means that parsing can proceed in two steps: first, the block
structure of the document can be discerned; second, text lines inside
paragraphs, headings, and other block constructs can be parsed for inline
structure. The second step requires information about link reference
definitions that will be available only at the end of the first
step. Note that the first step requires processing lines in sequence,
but the second can be parallelized, since the inline parsing of
one block element does not affect the inline parsing of any other.

<a id="container-blocks-and-leaf-blocks"></a>

## 3.2 Container blocks and leaf blocks

<a id="container-blocks"></a>

<a id="leaf-blocks"></a>

We can divide blocks into two types:
[container blocks](003-2-2-tabs.md#container-blocks),
which can contain other blocks, and [leaf blocks](003-2-2-tabs.md#leaf-blocks),
which cannot.

# 4 Leaf blocks

This section describes the different kinds of leaf block that make up a
Markdown document.

<a id="thematic-breaks"></a>

## 4.1 Thematic breaks

<a id="thematic-break"></a>

A line consisting of 0-3 spaces of indentation, followed by a sequence
of three or more matching `-`, `_`, or `*` characters, each followed
optionally by any number of spaces or tabs, forms a
[thematic break](003-2-2-tabs.md#thematic-break).

<a id="example-13"></a>

[Example 13](003-2-2-tabs.md#example-13)



```
***
---
___
```






```
<hr />
<hr />
<hr />
```




Wrong characters:

<a id="example-14"></a>

[Example 14](003-2-2-tabs.md#example-14)



```
+++
```






```
<p>+++</p>
```




<a id="example-15"></a>

[Example 15](003-2-2-tabs.md#example-15)



```
===
```






```
<p>===</p>
```




Not enough characters:

<a id="example-16"></a>

[Example 16](003-2-2-tabs.md#example-16)



```
--
**
__
```






```
<p>--
**
__</p>
```




One to three spaces indent are allowed:

<a id="example-17"></a>

[Example 17](003-2-2-tabs.md#example-17)



```
 ***
  ***
   ***
```






```
<hr />
<hr />
<hr />
```




Four spaces is too many:

<a id="example-18"></a>

[Example 18](003-2-2-tabs.md#example-18)



```
    ***
```






```
<pre><code>***
</code></pre>
```




<a id="example-19"></a>

[Example 19](003-2-2-tabs.md#example-19)



```
Foo
    ***
```






```
<p>Foo
***</p>
```




More than three characters may be used:

<a id="example-20"></a>

[Example 20](003-2-2-tabs.md#example-20)



```
_____________________________________
```






```
<hr />
```




Spaces are allowed between the characters:

<a id="example-21"></a>

[Example 21](003-2-2-tabs.md#example-21)



```
 - - -
```






```
<hr />
```




<a id="example-22"></a>

[Example 22](003-2-2-tabs.md#example-22)



```
 **  * ** * ** * **
```






```
<hr />
```




<a id="example-23"></a>

[Example 23](003-2-2-tabs.md#example-23)



```
-     -      -      -
```






```
<hr />
```




Spaces are allowed at the end:

<a id="example-24"></a>

[Example 24](003-2-2-tabs.md#example-24)



```
- - - -    
```






```
<hr />
```




However, no other characters may occur in the line:

<a id="example-25"></a>

[Example 25](003-2-2-tabs.md#example-25)



```
_ _ _ _ a

a------

---a---
```






```
<p>_ _ _ _ a</p>
<p>a------</p>
<p>---a---</p>
```




It is required that all of the [non-whitespace characters](002-1-3-why-is-a-spec-needed.md#non-whitespace-character) be the same.
So, this is not a thematic break:

<a id="example-26"></a>

[Example 26](003-2-2-tabs.md#example-26)



```
 *-*
```






```
<p><em>-</em></p>
```




Thematic breaks do not need blank lines before or after:

<a id="example-27"></a>

[Example 27](003-2-2-tabs.md#example-27)



```
- foo
***
- bar
```






```
<ul>
<li>foo</li>
</ul>
<hr />
<ul>
<li>bar</li>
</ul>
```




Thematic breaks can interrupt a paragraph:

<a id="example-28"></a>

[Example 28](003-2-2-tabs.md#example-28)



```
Foo
***
bar
```






```
<p>Foo</p>
<hr />
<p>bar</p>
```




If a line of dashes that meets the above conditions for being a
thematic break could also be interpreted as the underline of a [setext
heading](004-4-2-atx-headings.md#setext-heading), the interpretation as a
[setext heading](004-4-2-atx-headings.md#setext-heading) takes precedence. Thus, for example,
this is a setext heading, not a paragraph followed by a thematic break:

<a id="example-29"></a>

[Example 29](003-2-2-tabs.md#example-29)



```
Foo
---
bar
```






```
<h2>Foo</h2>
<p>bar</p>
```




When both a thematic break and a list item are possible
interpretations of a line, the thematic break takes precedence:

<a id="example-30"></a>

[Example 30](003-2-2-tabs.md#example-30)



```
* Foo
* * *
* Bar
```






```
<ul>
<li>Foo</li>
</ul>
<hr />
<ul>
<li>Bar</li>
</ul>
```




If you want a thematic break in a list item, use a different bullet:

<a id="example-31"></a>

[Example 31](003-2-2-tabs.md#example-31)



```
- Foo
- * * *
```






```
<ul>
<li>Foo</li>
<li>
<hr />
</li>
</ul>
```
