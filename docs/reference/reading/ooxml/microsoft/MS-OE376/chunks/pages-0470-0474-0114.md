2.1.1059         Part 4 Section 3.17.7.272, RIGHT

a.   The standard specifies that RIGHT is intended for use with languages that use the single-byte
     character set (SBCS), whereas RIGHTB is intended for use with languages that use the double-
     byte character set (DBCS).

     In Office, RIGHT is intended for use with any language, whereas RIGHTB is intended for use with
     languages that use the double-byte character set (DBCS).


2.1.1060         Part 4 Section 3.17.7.273, RIGHTB

a.   The standard does not specify which languages support DBCS.

     In Office, the languages that support DBCS include Japanese, Chinese (Simplified), Chinese
     (Traditional), and Korean.

b.   The standard does not specify behavior of RIGHTB when default language supports DBCS and
     when it does not support DBCS.

     In Office, when the default language supports DBCS, RIGHTB counts each double-byte character
     as 2 bytes, and each single-byte character as 1. When the default language does not support
     DBCS, RIGHTB counts each character as 1 byte.


2.1.1061         Part 4 Section 3.17.7.274, ROMAN

a.   The standard does not specify what happens if number argument is equal to 0.

     Office returns the empty string if number argument is equal to 0.


2.1.1062         Part 4 Section 3.17.7.275, ROUND

a.   The standard states that a return value is the rounded down value of x.

     Office treats x as the rounded value of x.


2.1.1063         Part 4 Section 3.17.7.279, ROWS

a.   The standard states that if the range of cells referred to by array is not contiguous, #NULL! is
     returned.

     Office returns #REF!, if array refers to the union of discontiguous ranges.


2.1.1064         Part 4 Section 3.17.7.280, RSQ

a.   The specification for the RSQ function states the equation for the Pearson product moment
     correlation coefficient but does not give an accurate meaning of the variables.

     Office defines x as a sample value, x-bar as the sample mean AVERAGE(known-xs), y as a sample
     value, and y-bar as the sample mean AVERAGE(known-ys)


2.1.1065         Part 4 Section 3.17.7.281, RTD

a.   The standard does not describe restrictions on progID.

     In Office, if progID does not reference an application that is registered and that implements
     IRTDServer, then #N/A is returned.

a.   The standard does not specify how function arguments map to formula variables.

     Office maps x-bar to the sample mean AVERAGE (known-xs) argument and y-bar to the sample

2.1.1071         Part 4 Section 3.17.7.296, STDEV

a.   The standard maps x to the sample mean and n to the sample size.

     Office maps x-bar to the sample mean, n to the sample size and x to a sample value.

b.   The standard does not specify what happens if sample size is less than or equal to 1.

     Office returns #DIV/0! if sample size is less than or equal to 1.


2.1.1072         Part 4 Section 3.17.7.297, STDEVA

a.   The standard maps x to the sample mean and n to the sample size.

     Office maps x-bar to the sample mean, n to the sample size and x to a sample value.

b.   The standard does not specify what happens if size is less than or equal to one.

     Office returns #DIV/0! if sample size is less than or equal to one.


2.1.1073         Part 4 Section 3.17.7.298, STDEVP

a.   The standard maps x to sample value, x-bar to sample mean, and n to the sample size.

     Office maps x to a population value, x-bar to the population mean, and n to the population size.

b.   The standard states that if data represents a population sample only, STDEVA should be used.

     In Office, STDEV should be used in this case.

c.   The standard does not specify what happens if population size is 0.

     Office returns #DIV/0! if population size is 0.


2.1.1074         Part 4 Section 3.17.7.299, STDEVPA

a.   The standard maps x to sample value, x-bar to sample mean, and n to the sample size.

     Office maps x to a population value, x-bar to the population mean, and n to the population size.
